# TechPickr

TechPickr is a React + Vite PC and laptop advisor. Gemini recommendations are generated by a small Node backend so the Gemini API key is never part of the browser build. Supabase Auth manages accounts and saved recommendations are protected by your Supabase RLS policies.

## Configure environment

Keep the existing `.env.local` if it already contains valid Supabase values. Otherwise, from the project directory copy `.env.example` to `.env.local`, then set:

```dotenv
VITE_SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_SUPABASE_PUBLISHABLE_OR_ANON_KEY
VITE_SUPABASE_GOOGLE_AUTH_ENABLED=false
```

For Gemini, copy `server/.env.example` to the project-root `.env` and set `GEMINI_API_KEY`. `GEMINI_API_KEY` belongs only in that backend `.env` file; never put it in `.env.local`, a `VITE_` variable, or browser code. Both `.env` and `.env.local` are ignored by Git. Do not replace existing valid environment values.

Google sign-in is shown only when `VITE_SUPABASE_GOOGLE_AUTH_ENABLED=true` and Google OAuth is configured in the Supabase dashboard. Email/password authentication works independently.

## Supabase setup

Create `public.profiles` and `public.saved_recommendations` using the schema described in the project request. Enable RLS. The app never creates or recreates tables and never calls the former PC-builder RPC. The old SQL migration/diagnostic files remain as historical database scripts only.

Example policies for the operations used by the app (apply only after the tables exist; do not add duplicate policy names):

```sql
alter table public.profiles enable row level security;
alter table public.saved_recommendations enable row level security;

create policy "profiles_select_own"
on public.profiles for select to authenticated
using ((select auth.uid()) = id);

create policy "saved_recommendations_select_own"
on public.saved_recommendations for select to authenticated
using ((select auth.uid()) = user_id);

create policy "saved_recommendations_insert_own"
on public.saved_recommendations for insert to authenticated
with check ((select auth.uid()) = user_id);

create policy "saved_recommendations_delete_own"
on public.saved_recommendations for delete to authenticated
using ((select auth.uid()) = user_id);
```

Do not grant anonymous access. The frontend sends the authenticated session and relies on RLS; list queries do not download other users' rows for client-side filtering.

In Supabase Authentication settings, add your local and deployed callback URLs to the allowed redirect URLs. Local Vite uses `http://localhost:5173/my-recommendations`. If enabling Google, configure its provider credentials in Supabase first, then turn on the frontend flag.

## Install and run on Windows PowerShell

Run from the project folder (the directory containing `package.json`):

```powershell
npm.cmd install
```

Terminal 1 — Gemini backend:

```powershell
npm.cmd run dev:backend
```

Terminal 2 — frontend:

```powershell
npm.cmd run dev
```

Open the URL printed by Vite. The Vite development proxy forwards `/api` requests to `http://127.0.0.1:3001`. For a production deployment, deploy the Node backend separately, set its `FRONTEND_ORIGIN`, and set frontend `VITE_RECOMMENDATION_API_URL` to the backend origin before building.

The frontend is configured for the `/TechPickr/` GitHub Pages path. Its `404.html` fallback preserves deep links so refreshing pages such as `/my-recommendations` restores the route before React Router starts.

Useful checks:

```powershell
npm.cmd run build
npm.cmd run lint
Invoke-RestMethod http://127.0.0.1:3001/api/health
```

Health output reports whether Gemini is configured, but never returns the key.

## Manual test checklist

1. Register using email/password. If Supabase email confirmation is enabled, confirm the email before logging in.
2. Log in, refresh the page, and confirm the account remains signed in; log out from the navigation bar.
3. Complete the laptop questionnaire and the PC builder separately. Confirm each uses Gemini and displays a notice that facts/prices/availability are not live-verified.
4. Save each recommendation. When signed out, confirm the app routes to login and then saves the pending recommendation without generating again.
5. Open **My Recommendations**, expand an entry to inspect its original requirements and saved response, then delete it and confirm removal.
6. Test an account with no saved entries for the empty state. Confirm a second user cannot read or delete the first user's entries under RLS.
7. If testing deployment, verify the Gemini key is absent from `dist` and from browser network requests.

Live Gemini, authentication and database operations require your own configured credentials and database setup; successful local builds do not test those external services.
